# v27b 1~5장 조판 기록

2026-11-14. v26 생성기 복사본(`scripts/pitchdeck/build_pitchdeck_v27b.js`)에서 1장 표지~5장 비교 OX만 다시 잡았다.
문장·숫자·발표자 노트·장 수는 바꾸지 않았고, `washImage`, `box` 기본값, `K` hex, `diag`, `lightSlide` 같은 표면 함수는 고치지 않았다.
호출할 때 넘기는 radius·shadow·color·좌표·글자 크기만 바꿨다.

## 2장 문제 인식 — 사실 카드 네 장

| 요소 | 이전 | 이후 |
|---|---|---|
| 카드(`problemCard`) 모서리 | radius 0.18 | **0.05** |
| 카드 그림자 | 있음 | **끔** |
| 카드 선 | `E7D0E4` | **`K.line`(E4DCEC) 1pt** |
| 카드 첫 줄 색 | `K.electro` (카드마다 1곳, 모두 4곳) | **`K.ink`** |
| 카드 네 장 높이·좌표 | 2.16, pcY1 1.88 / pcY2 4.16 | 그대로 (같은 행 위·아래·높이 동일) |
| 사람과 카드를 잇는 선 | `diag()` → `K.electro`, 두께 0.02in(≈1.4pt) | **인라인 RECTANGLE, `K.silver`, 0.01in(≈0.72pt)**, 각도 계산 동일 |
| 머리 고리 | `K.electro` 1.75pt | **`K.silver` 1.25pt** |
| 「네 갈래가 여기로 모임」 | `K.electro` | **`K.mute`** |

`diag()`는 표면 함수라 고치지 않고, 2장에서만 같은 계산으로 은색 실선을 직접 그렸다. 네 선의 출발점은 카드 오른쪽·왼쪽 변 중앙이고 도착점은 사람 원 가장자리라, 선의 상자가 「입찰 담당자」(y 4.93)와 「네 갈래가 여기로 모임」(y 5.04) 위를 지나지 않는다(선 상자 y 4.85). 원 안 그림, 도형 안 숫자(87.995% → 89.995%, 2017-04-11 등)와 출처 주석은 그대로다.

일렉트로 퍼플을 남긴 요소: **제목 핵심어 「담당자 머리만 아픔」**(`lightSlide`가 넘기는 accent). (v26은 11곳)

## 5장 비교 OX — 7행 유지, 세 행만 약하게

| 요소 | 이전 | 이후 |
|---|---|---|
| 기호 열·글자 열 분리 | 9열(항목·기호·글자 ×4) | 그대로 — 기호가 한 세로줄 |
| 행 수 | 헤더 + 7행 | 그대로 (빼지 않음) |

| BidBox 열 바탕 | 7행 모두 `K.electroTint` | **상위 3행(규칙표 고르기·기준 없을 때·세 가지 금액)만 `K.electroTint`**, 나머지 4행 흰색 |
| BidBox 글자 색 | `K.ink` | 상위 3행 `K.ink`, **나머지 4행 `K.mute`** |
| 항목 열 글자 색 | `K.ink` | 상위 3행 `K.ink`, **나머지 4행 `K.mute`** |

`pair()`에 세 번째 인자(강조 여부)만 더했다. 문자열은 건드리지 않았고, 글자 굵기는 `PITCH_QUIET` 기본값에서 표 칸이 이미 보통으로 내려가므로 값 변화가 없다.

일렉트로 퍼플을 남긴 요소: **제목 핵심어 「OX로」**. (v26과 같은 1곳)

## 확인하지 못한 것

- 이 Mac의 LibreOffice는 맑은 고딕이 없어 한글을 빈칸으로 그린다. 위 겹침 검사는 도형 좌표 기준이고, 실제 글자 폭으로 줄이 바뀌는 곳(2장 카드 보조 줄, 4장 수집 칸 두 번째 줄)은 Word나 구글 슬라이드에서 한 번 더 봐야 한다.
- 바탕 무늬 불투명도(디자인_방향 7항)는 `washImage`·`lightBgImage` 안에 있어 이번 범위 밖이라 손대지 않았다. 표지·2~5장의 무늬는 v26과 같은 세기다.
- 4장 「확인된 규칙만 계산」 줄은 v26에도 상자가 없어 그대로 두었다.
