# 쉬운 말로 쓰기 (사용자 지정, 2026-11-04)

사용자가 받은 의견: 「사업계획서 내용이 어렵다」. 사용자 지정 기준은 **초등학교 3학년도 알아들을 수준**이다. v27부터 새로 쓰거나 고치는 모든 문장에 이 문서를 적용한다. `voice.md`(대표자 목소리), AGENTS.md의 명사 종결·사실 규칙과 함께 지킨다. 셋이 부딪히면 사실 규칙 → 명사 종결 → 쉬운 말 → 목소리 순으로 따른다.

## 1. 목표

입찰을 해 본 적 없는 사람이 칸 하나를 한 번 읽고 아래 세 가지를 말할 수 있으면 통과다.

1. **누가** 어떤 일에서 막히는지 (청소·경비·파견·직업소개 회사가 공공기관 입찰에서)
2. **무엇이** 그 일을 대신해 주는지 (BidBox가 공고를 열면 계산 규칙과 금액을 보여 줌)
3. **어디까지** 하는지 (규칙을 못 찾으면 멈춤, 낙찰은 보증하지 않음)

심사위원 중에는 조달 전문가도 있다. 그래서 정확한 용어는 지우지 않고 **쉬운 말 뒤 괄호**에 남긴다.

## 2. 규칙

| 번호 | 규칙 | 전 → 후 |
|---|---|---|
| 1 | **쉬운 말 먼저, 용어는 괄호.** 전문 용어는 장(□)마다 처음 나올 때 3절 바꿈표의 쉬운 말을 앞에 쓰고 용어를 괄호에 둔다. 같은 장에서 두 번째부터는 용어만 써도 된다 | 적용 별표 판정 → 공고에 맞는 계산 규칙표(별표) 찾기 |
| 2 | **한 문장에 한 가지.** 괄호 안(풀이·출처)을 뺀 글자 수로 본문 문장은 60자, 표 칸 문장은 45자를 넘으면 나눈다. 양식이 한 줄 이름을 요구하는 칸(창업아이템명, 명칭, 범주)은 길이와 풀이 규칙의 예외이고, 풀이는 바로 다음 칸에서 한다. 쉼표로 이은 절이 셋 이상이면 글머리(◦)로 나눈다 | 「…를 열면 A, B, C, 근거를 한 화면에서 확인. 규칙을 특정할 수 없으면 계산 중단. 기술은 …」 → 글머리 3줄 |
| 3 | **장면으로 시작.** 문제 칸은 「누가, 언제, 무엇 때문에」 막히는지 한 장면으로 먼저 쓰고, 숫자는 그 뒤에 근거로 붙인다 | 「기준값은 첨부 세부기준에만 존재」 → 「입찰 점수를 계산하려면 … 숫자가 필요하지만 이 내용은 첨부 파일에만 있음」 |
| 4 | **숫자는 그대로, 감은 덧붙여.** 숫자·출처·날짜는 바꾸지 않는다. 퍼센트나 큰 수 옆에 같은 뜻의 쉬운 비교를 괄호로 붙일 수 있다. 원래 숫자에서 바로 나오는 비교만 쓰고 새 숫자를 만들지 않는다 | 9,911건(31.7%) → 9,911건(31.7%, 10건 중 3건꼴) |
| 5 | **기호·약어 줄이기.** B, k, %p, SaaS, B2B, API, OCR, TAM·SAM·SOM 같은 약어는 장마다 처음에 풀이를 붙이거나 쉬운 말로 바꾼다. 제품 이름(BidBox, Narani)과 AI는 그대로 둔다 | 가격점수 기준값(B, k, 기준비율, 통과점수) → 계산에 넣는 숫자(기준값) |
| 6 | **「~의」 세 번 연속 금지.** 「A의 B의 C의 D」는 풀어 쓴다 | 시행일·기관별 규칙의 판본의 차이 → 기관과 시행일마다 다른 규칙 |
| 7 | **나열은 표로.** 기능·일정·결과물처럼 셋 이상 나열하면 칸 안에 작은 표(머리 한 줄 + 글머리)나 화면 이미지로 바꾼다. 같은 표에 이미 있는 이미지는 다시 넣지 않는다 | v27 산출물 칸(화면 2장 + 설명), 실현 가능성 칸(지금 되는 것 / 만들 것) |
| 8 | **명사 종결은 쉬운 명사로.** AGENTS.md 명사 종결은 그대로 지키되 「~함」「~존재」 대신 「확인」「표시」「없음」「있음」처럼 짧은 말로 끝낸다. 조사(「~에」「~로」)로 끝내지 않는다 | 「…한 화면에.」 → 「…한 화면에서 확인.」 |

## 3. 쉬운 말 바꿈표

용어가 처음 나올 때 왼쪽 대신 가운데를 쓰고 괄호에 용어를 둔다. 여기 없는 용어는 같은 방식으로 이 표에 더한다(사실이 바뀌지 않는 풀이만).

| 용어 | 쉬운 말 | 메모 |
|---|---|---|
| 용역 | 사람이 하는 일(청소·경비·파견·직업소개) | 물품·공사와 구분할 때만 「용역」을 쓴다 |
| 적격심사 | 가격과 회사 점수를 함께 보고 일을 맡길 회사를 고르는 입찰 | |
| 낙찰 / 낙찰자 | 일을 따냄 / 일을 따낸 회사 | 「낙찰 보증」 같은 약속은 쓰지 않는다 |
| 투찰 / 투찰 금액 | 입찰에 써 내는 금액 | |
| 낙찰률 | 기관이 정한 기준 금액에 비해 따낸 금액이 몇 %인지 | |
| 예정가격·기초금액 | 기관이 미리 정한 기준 금액 | |
| 별표·세부기준·배점표 | 점수 계산 규칙표 | |
| 가격점수 기준값(B, k, 기준비율, 통과점수) | 계산에 넣는 숫자(기준값) | 기호는 2-1절 이후 필요한 곳에서만 |
| 산식 | 계산식 | |
| 판본·개정본 | 옛 판과 고친 판 | |
| 규칙 판정 | 공고에 맞는 계산 규칙 찾기 | |
| 계산 차단·계산 중단 | 규칙을 못 찾으면 틀린 금액 대신 계산을 멈춤 | |
| 최저가·AI 예측가·최상가 | 써도 되는 가장 낮은 금액·AI가 예상한 금액·가장 높은 금액 | 셋을 묶어 「세 가지 금액」 |
| 신용등급·신인도 | 회사 신용 점수·회사 평판 점수 | |
| 평균 절대오차 1.1885%p | 낙찰률 예측이 실제와 평균 1.1885%p 차이 | %p는 「퍼센트포인트」로 한 번 풀이 |
| 면허 | 업종 허가(면허) | |
| 파일럿 | 시험 사용(파일럿) | |
| 토큰 | 이용권(토큰) | 1토큰 1,000원(가설)은 그대로 |
| SaaS / B2B | 인터넷으로 쓰는 구독형 프로그램 / 회사 대상 | |
| API | 다른 프로그램이 연결해 쓰는 통로(API) | |
| OCR | 사진 속 글자 읽기(OCR) | |
| TAM / SAM / SOM | 전체 시장 / 우리가 닿을 수 있는 시장 / 처음 들어갈 시장 | |
| 지자체 | 시·군·구청 같은 지방 기관(지자체) | |
| 중간평가 | 사업 중간 점검(중간평가) | |
| 색인 | 찾기 쉽게 정리해 둔 공고 | |

## 4. 지키는 선

- **쉬운 말이 사실을 넘으면 안 된다.** 「꼭 따내는」, 「이기는 금액」, 「정답 금액」처럼 낙찰을 약속하는 말은 쓰지 않는다. 「써 낼 금액의 범위를 알려 줌」까지만.
- 비유는 계획서 사실 안에서만 쓴다. 새 숫자, 새 기능, 새 고객 이야기를 만들지 않는다.
- 쉬운 말로 길어지면 다른 문장을 줄여 12쪽을 지킨다. 쪽수는 `count_pages.sh`로 잰다.
- 공고 양식의 항목 이름(「문제 인식(Problem)」 등)과 표 제목은 바꾸지 않는다.

## 5. 점검

```bash
python3 -I .agents/skills/bizplan-writing/scripts/check_plain.py <계획서.docx>
```

긴 문장, 장마다 풀이 없이 처음 나온 용어, 약어, 「~의」 연쇄, 조사로 끝난 문장을 문단 번호와 함께 뽑는다. 후보일 뿐이고, 고칠 때는 2절 규칙과 4절의 선을 따른다. 보고에는 수정 전후 후보 수를 적는다.

## 6. 적용 기록

- v27(2026-11-04): 일반현황 표, 창업 아이템 개요(요약) 표에 처음 적용.
- v28(2026-11-04): 1~4장 본문 1차 적용(154곳). 한 장씩 적용하며 잰 쪽수는 1장까지 12쪽, 2장까지 13쪽이었고, 빈 표 행 5개 삭제와 겹치는 문단 1개 삭제로 12쪽에 맞췄다.
- 같은 낱말이 뜻이 다르면 쉬운 말도 다르게 쓴다. 고객이 사는 「토큰」은 이용권(토큰), 운영비의 「API 토큰」은 AI 사용료(API 토큰).
- 점검 스크립트의 한계: 1~4장 제목이 그림 배너라 스크립트가 장을 나누지 못한다. 「풀이 없는 첫 용어」는 개요표 이후를 한 장으로 보고 센다. 「계산식」 안의 「산식」처럼 더 긴 낱말 속에 든 용어도 후보로 잡힌다.
