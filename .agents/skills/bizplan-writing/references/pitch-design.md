## 3. v11에 넣을 값

### 3-1. 글자 사다리

본문 장 제목은 마스터 한 자리라 장마다 크기가 다를 수 없다. 가장 긴 제목(고객 장, 약 36자)이 32pt에서 두 줄이 된다. 그 크기를 전 본문 장의 제목으로 쓴다.

### 3-2. 여백과 간격

- 좌우 여백은 0.6인치를 유지한다(최소 0.5인치).

- 주석·본문의 맨 아래는 y 6.75 이하에서 끝난다. 꼬리말 로고(y 7.03)와의 간격은 0.28인치 이상.
- 꼬리말 로고와 쪽 번호는 장식이다. 슬라이드 맨 아래 0.5인치를 비우려고 꼬리말을 위로 올리지 않는다. 본문과 주석이 꼬리말 위에 0.28인치 간격을 두면 된다.
- 간격을 한 장만 0.5, 옆 장은 0.15처럼 섞지 않는다. 본문 장은 0.30을 기본으로 하고, 아래 예외만 더 좁다.

### 3-3. 명암 리듬

v11에서 바꾸는 어두운 장은 자금 장(「자금: 정부지원 4,000만 원」) 하나다. `darkSlide`로 만들고, 그 장의 글자·칸·막대를 어두운 장 토큰으로 전부 바꾼다.

| 역할 | 밝은 장 | 자금 장(어두움) |
|---|---|---|
| 바탕 | `K.page` | `K.navy` |
| 카드 | `K.white` | `K.navy3` |
| 제목·본문 | `K.ink` / `K.ink2` | `K.white` / `K.onDarkMute` |
| 강조 | `K.blue` | `K.skyOnDark` |
| 상태 색 | `K.green` `K.amber` `K.red` | `K.greenOnDark` `K.amberOnDark` `K.redOnDark` |

자금 장 안에 흰 카드를 하나 남기지 않는다. 시장 장(중첩 원, 업종 막대)은 밝은 장으로 두고 숫자만 3-1대로 키운다. 시제품·근거 상담·개발 현황 숫자는 어두운 장 그대로다. 자금 장 다음의 사회적 가치·팀은 밝은 장 두 장으로 닫는다.

일정부터 로드맵까지 밝은 장이 여섯 장 이어진다. 그 여섯 장은 같은 흰 카드 세 열을 반복하지 않게, 이미 있는 도식(일정 점, 시장 원, 수익 흐름, 영업 두 열, 검증 두 칸, 로드맵 기둥)의 숫자와 도형을 3-1 크기로 키운다. 시장 장을 일부만 어둡게 만들지 않는다.

### 3-4. 생성기 제약

이 생성기가 이미 지키는 것이다. v11에서도 유지한다.

- 색은 6자리 hex. `#`을 붙이지 않는다. 투명도는 `opacity`로 쓴다. react-icons에 넘기는 SVG 색만 `"#" + 토큰`이다.
- 그림자는 `box()` 호출 안에서 새 객체를 만든다. 그림자 객체 하나를 여러 `addShape`에 넘기지 않는다.
- `rectRadius`는 `ROUNDED_RECTANGLE`에만 둔다.
- 제목 아래에 강조선을 그리지 않는다. 구분은 여백과 바탕색으로 한다.
- 막대는 도형이다. 네이티브 막대 차트는 구글 슬라이드 변환에서 항목 이름·순서·숫자 형식이 깨진다. 도넛 차트는 그대로 둔다.
- 로고는 `scripts/pitchdeck/assets/`의 투명 로고. 비율 870:308.
- v19부터 P·S 워터마크는 그리지 않는다. 카드 뒤에서 반원·화살촉 조각처럼 잘려 보였다(`PITCH_MARK=1`이면 v18까지 모습).
- v19부터 카드 뒤 판(`plate`)은 카드와 같은 위·아래 선에 맞출 때만 쓰고, 카드가 판 테두리를 덮거나 판과 조금 어긋나게 두지 않는다. 같은 줄 카드는 같은 크기·같은 높이에 둔다(가운데만 크게·높게 띄우지 않는다).
- 금액 비율을 보여 주는 원은 넓이를 금액에 비례시킨다(지름 = √비율). 비교하는 막대는 같은 출발선에 둔다.
- 큰 숫자는 26pt 이상이어야 파랑이 남는다(QUIET 규칙). 그보다 작으면 회색으로 바뀐다.
- v20부터 어두운 장 다섯 장(표지·근거 상담·숫자·자금·마무리)에만 생성기가 코드로 그린 추상 무늬 바탕을 깐다(`bgImage`, `setBg`). 한 언어(브랜드 파랑의 옅은 점·선)에 단락 뜻만 모양으로 바꾼다(모이는 곡선·연결망·동심원). v22부터 밝은 장은 제목 오른쪽 위 빈 띠에만 깐다(`lightBgImage`, 띠 밖 clipPath, 오른쪽 위 기준 mask로 흐려짐). 도표·카드 뒤에는 깔지 않는다. 무늬의 점이나 원이 장 가장자리에서 반원으로 잘리지 않게 장 안쪽에 두고, 눈썹·제목·꼬리말 로고·쪽 번호 자리에는 점을 두지 않는다. 스톡·AI 생성 그림은 쓰지 않는다(출처·이용 조건).
- 검수는 구글 슬라이드 썸네일로 한다(이 Mac의 LibreOffice는 한글이 빈칸). 고친 장과 이웃 장을 다시 받아 본다.
- 제목의 `[[핵심어]]`만 강조색이다.
- 제품 화면은 비율을 유지한다. 폭과 높이를 따로 늘려 늘이지 않는다.

## 4. 문장과 숫자

2026-11-10 사용자 지정(v17). 장에 보이는 설명 문장을 줄인다. 장에는 제목의 한 주장, 짧은 라벨, 숫자, 출처, 가설, 「낙찰 보증 없음」을 남긴다. 장에서 뺀 설명은 발표자 노트에 둔다. 숫자·출처·날짜는 바꾸지 않는다. v16 문장으로 되돌리지 않는다. v16까지의 「글자 수를 맞추려고 문장을 빼지 않는다」는 그 판까지만 적용한다.

밀도는 3절의 여백과 글자 사다리다. 쉬운 말은 `plain.md`를 따르고, 계획서 본문의 명사 종결(「~다」를 빼는 규칙)은 피치덱에 소급하지 않는다.

이미 확정된 표현을 되돌리지 않는다.

- 「모르면 멈춘다」로 되돌리지 않는다. 지금 문장은 「확인된 규칙만 계산」, 「없으면 직접 입력」, 「확인하지 못한 공고는 금액을 비우고 직접 입력」이다.
- 낙찰을 보증하는 말을 넣지 않는다. 마무리의 「낙찰 보증 없음」을 유지한다.
- 근로조건을 사회적 가치 카드로 넣지 않는다.
- 수집은 매일 새벽 2시, 방금 가져온 것만 반영. 505,271건 전체를 다시 만든다고 쓰지 않는다.
- 다시 배움은 개발 실행, 매주 월요일 새벽 3시, 용역 모델. 교체는 사람. 운영은 꺼져 있고 알림만. 자동으로 바뀐다고 쓰지 않는다.
- 새 숫자, 새 가격, 새 성능(오차가 줄었다는 값 포함)을 만들지 않는다. 숫자는 `AGENTS.md`와 생성기에 있는 것만 쓴다.

## 5. 작업 순서

1. 이 파일과 `AGENTS.md` 「피치덱」을 읽는다.
2. 생성기를 고친다. v10 pptx는 복사하거나 덮어쓰지 않는다.
3. 의존성이 없으면 `/tmp/pitch-deps`에 `pptxgenjs`, `react`, `react-dom`, `react-icons`, `sharp`를 설치한다.
   ```bash
   NODE_PATH=/tmp/pitch-deps/node_modules node scripts/pitchdeck/build_pitchdeck.js \
     02_과제/피치덱/BidBox_피치덱_v11.pptx
   ```
4. 장을 이미지로 본다. 슬라이드 스킬의 렌더를 쓴다.
   ```bash
   python3 ~/.grok/bundled/skills/pptx/scripts/render_slides.py \
     02_과제/피치덱/BidBox_피치덱_v11.pptx --output_dir /tmp/pitch-v11
   ```
   렌더가 실패하면 같은 스킬의 `soffice.py`로 PDF를 만들고 `pdftoppm`으로 장을 나눈다. 이 Mac의 LibreOffice는 맑은 고딕이 없으면 한글 폭이 달라진다. 겹침과 잘림은 이미지로 보고, 글자 폭의 최종 판정은 PowerPoint로 남긴다.
5. 압축을 풀어 겹침을 검사한다.
   ```bash
   python3 ~/.grok/bundled/skills/pptx/scripts/office/unpack.py \
     02_과제/피치덱/BidBox_피치덱_v11.pptx /tmp/pitch-v11-unpacked
   python3 ~/.grok/bundled/skills/pptx/scripts/check_overlaps.py /tmp/pitch-v11-unpacked
   python3 ~/.grok/bundled/skills/pptx/scripts/detect_fonts.py \
     02_과제/피치덱/BidBox_피치덱_v11.pptx
   ```
   제출 pptx의 글꼴은 맑은 고딕만이다. `check_overlaps.py --fix`의 자동 축소는 쓰지 않는다. 겹치면 생성기의 자리와 3-1의 한 단계(14→13pt)로 고친다.
6. 장마다 겹침, 잘림, 0.24인치보다 좁은 간격(예외 표 제외), 제목과 본문 충돌, 낮은 대비를 적는다. 한 군데를 고친 뒤 그 장과 이웃 장을 다시 렌더한다. 한 바퀴를 돌려 새 문제가 없을 때 v11이라고 적는다.
7. 검사가 끝나면 1절의 적용 상태와 상태 줄 세 곳의 「피치덱」을 새 버전으로 바꾼다. 검토용 구글 슬라이드는 사용자가 올리라고 한 뒤에 `gslides.md`로 같은 링크에 덮어쓴다. v17은 2026-11-10에 올렸다(장 21, Noto Sans KR 2138, Arial 172, 맑은 고딕 0). v16은 2026-11-09에 올렸고 버전 기록에 남아 있다(장 21, Noto Sans KR 2356, Arial 172, 맑은 고딕 0). v15는 2026-11-09에 올렸다(장 21, Nanum Gothic 2356, Arial 172, 맑은 고딕 0). v14는 2026-11-07에 올렸다(장 21, Nanum Gothic 2364, 맑은 고딕 0). v13은 2026-11-07에 올렸다(장 21, Nanum Gothic 2364, 맑은 고딕 0). v12는 2026-11-06에 올렸다(장 21, Nanum Gothic 2356, 맑은 고딕 0).
